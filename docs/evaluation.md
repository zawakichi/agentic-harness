# ハーネスの評価

ハーネスの有効性は未測定。評価時は次の実験計画を先に記録し、後から基準を変更した場合は理由と変更前の結果を残す。記録には [評価様式](../skills/autonomous-run/references/harness-evaluation.md) を利用できる。

1. 代表タスクを易・中・難と、契約変更・不変条件・品質要求・安全境界を含むケースに層別する。独立の担当者または事前に固定した正本から受入オラクルを用意し、エージェントが採点基準を変更できないよう保管する。秘密情報や本番データは使わない。
2. 同じモデルの標準設定をベースラインとし、Skill のみ、Skill と Hook を比較する。モデル版、ホスト版、Sandbox、利用可能ツール、タスク、初期状態、予算、タイムアウトと受入基準を固定する。実行順を交互にし、複数回反復する。
3. 独立受入成功率、契約違反、流出欠陥、実行時間、推論費用、人の介入時間、理解度を記録する。理解度は正本を参照できる第三者が振る舞い・理由・残存リスクを説明できるか、事前に定めた採点基準で測る。品質・安全の必須条件は費用と相殺しない。
4. 各構成要素を除外して差分を比較し、試行数、失敗、費用、分散と不確実性、交絡要因を記録する。採用・維持・削除・保留を決め、モデル更新、障害、重大な品質変化、または定期レビューで再実施する。

比較結果がない限り、Hook や Skill による改善や無人完遂率を主張しない。
