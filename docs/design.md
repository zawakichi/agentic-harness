# 設計の正本

この文書は Plugin の設計意図と保証範囲の正本。実際にエージェントへ渡す作業上の契約は [autonomous-run](../skills/autonomous-run/SKILL.md) を正本とする。既存プロジェクトに導入した際の業務仕様や受入基準は、そのプロジェクトの既存の正本が優先される。

## 原則と適用

| 原則 | 判断基準 |
| --- | --- |
| Quality Attribute Driven | 自律性、セキュリティ、検証可能性、理解可能性と総コストを状況に応じて比較する。薄さは目的ではない。 |
| Semantic Integrity | 意味の単位ごとに権威ある正本を特定する。派生文書は参照を持ち、意図と既存実装を区別する。 |
| Human Understandability | 人が振る舞い、理由、トレードオフ、証拠、未検証事項を把握し、必要なら正本まで遡れる。 |
| Agent Autonomy | 達成方法や手順を固定せず、許可された範囲の可逆的な判断はエージェントに委ねる。 |
| Independent Verifiability | 合意済みの基準と独立した検証手段で判断する。実装者が用意したテストだけを独立性の根拠にしない。 |
| Evolution Adaptability | モデル、ホスト、費用の変化に応じて、構成要素の効果を測定し変更・削除する。 |

## 契約と設計手法

変更前に影響する既存の事前条件・不変条件・正常時と異常時の事後条件を特定し、正当に要求された変更以外は保持する。仕様が未整備なら実装を勝手に規範とせず、その不確実性を示す。既存の受入資産がない場合、別のオラクルや独立レビューを検討し、実現できなければ限界を報告する。

QAW は関係者の品質シナリオ抽出、ADD は設計ドライバーに基づく設計、ATAM は品質上のリスクとトレードオフの分析、CBAM は費用対効果の検討に役立つ。影響に応じて選択し、必要な範囲だけ使う。軽量な検討を正式な手法の実施と称しない。

## 採用と除外の判断

参考実装の正本の考え方、契約、選択的な手法、評価様式と小さな実行例を採用する。導入先に空の `AGENTS.md` や `docs/project.md` を自動配置せず、既存の仕様・CI・権限を尊重する。Skill は必要時に再利用できるため残す。SessionStart Hook はユーザーが求めた Plugin 構成として残し、Skill を知らせるだけに縮小する。Hook が実際に効果を持つかは未測定であり、[評価手順](evaluation.md)で判断する。独自ランナー、固定ステージ、全タスク向けの成果物作成は導入しない。いずれも将来の測定結果で見直す。

## 強制できる境界

Skill と Hook は指示であり、セキュリティ境界や検証基盤ではない。実際の権限、MCP、ネットワーク、秘密情報、独立した CI、ブランチ保護は利用者側で構成する。[Docker Sandboxes](docker-sandboxes.md) の microVM 内から呼ぶ MCP も、外部の権限を行使できる。保護された検証や受入基準を導入済みと仮定しない。

## Plugin の機能契約

- 事前条件: 対応ホストが Plugin を読み込み、利用者が適用対象のタスクと許可範囲を与える。Hook の実行はホストの対応と信頼設定に依存する。
- 不変条件: ホストの権限や承認ポリシー、利用者の指示、導入先の権威ある仕様と受入基準を Plugin 自体が上書きしない。必要な契約の意味や独立検証の基準を無断で緩めない。
- 正常時の事後条件: Hook は任意の Skill の存在を案内し、Skill は品質・契約・検証・報告に関する指針を提供する。エージェントの作業完了や品質達成を保証するものではない。
- 失敗・未対応時: Hook が利用できない場合も Skill の配布は独立している。ホストが Plugin を読み込めない、外部権限がない、または検証が不足する場合は、完了とみなさず制限を報告する。

この契約はホスト連携の意図であり、指示に従うこと自体を機械的に強制しない。パッケージの整合性は `tests/test_plugin.py` で検査する。実ホストでの Skill 呼び出しと Hook の信頼・実行は別途検証する。
